# AIF-Media-API

## What is this repository?

This is an implementation of the Service Configuration API, as proposed in [Active Inference for Sustainable Computing Continuum Systems](https://doi.org/10.1109/MIC.2025.3590621), and implemented in A Microservice-Based Platform for Sustainable and Intelligent SLO Fulfilment and Service Management. It specifically implements the API in the Media streaming use case.

It also includes some additional files for development, deployment, and testing.

## What do I need to run this?

At the very least, you will need a container runtime. `docker` is recommended, as it was used for testing and development, but `podman` may work too. `docker-compose` is recommended to run the container specification. You can also set up the containers manually or through other tools to follow the specification.

For proper testing, you may also want to create automated clients.

## Repository structure

- `hook_confs`: Stores configurations for the MQTT hooks in JSON format.
- `influxdb_conf`: InfluxDB configuration, provided empty for security reasons. **Create this directory if it does not exist**.
- `influxdb_data`: Data saved by InfluxDB, provided empty to avoid collision with new data. **Create this directory if it does not exist**.
- `jellyfin_conf`: Jellyfin configuration, provided empty for security reasons. **Create this directory if it does not exist**.
- `jelllyfin_data`: Media for Jellyfin to stream, provided empty for data size and copyright reasons. **Create this directory if it does not exist**.
    - `music`: Music files. Refer to the setup details below to replicate the experiment, or add your own. **Create this directory if it does not exist**.
    - `movies`: Video files. Refer to the setup details below to replicate the experiment, or add your own. **Create this directory if it does not exist**.
- `mqtt_hook`: Source code for the MQTT hook. Check its own `README.md` file.
- `service_api`: Implementation of the service API, based on the code generated by `openapi-generator`. Check its own `README.md` file.
- `slo_confs`: Stores configurations for the SLOs of the service API in JSON format.
- `telemetry_conf`: Configuration directory for the MQTT telemetry broker. This broker is used to get QoS information from the client side that is not directly obtained by the server.
    - `mosquitto.conf`: Configuration for the Mosquitto MQTT broker.
- `batch-openapi-generator.yaml`: Configuration for OpenAPI generator.
- `docker-compose-jellyfin-test.yaml`: Docker Compose specification for the scenario.
- `README.md`: Current file
- `ServiceAPIExample.yml`: Example declaration of the Service API using the OpenAPI specification.

### Instructions

1. Create the folders indicated above, if they do not already exist. Populate `jellyfin_data/music` and `jellyfin_data/movies` with the media you wish to use. **Make sure you have the legal right to offer this media in your jurisdiction**, even if you use the public domain or royalty-free media referenced above.
2. Start up Jellyfin: `docker-compose -f docker-compose-jellyfin-test.yaml up jellyfin`.
3. Access Jellyfin (by default at `http://localhost:8096`) and complete the setup.
4. Access the Dashboard at Jellyfin and generate an API key to be used in the test.
5. Fill the `JELLYFIN_API_KEY` environment variable of the `service-api` service in the Docker Compose specification with this newly-generated API key.
6. Bring down Jellyfin (`docker-compose -f docker-compose-jellyfin-test.yaml down`) and bring everything back up ( `docker-compose -f docker-compose-jellyfin-test.yaml up`.)
7. The platform is up! Point your Delock-11827 devices to send their data through MQTT to `<YOUR-IP>:1883` at topic `energy/<DEVICE-NAME>`. Configure and start up the Jellyfin auto-watchers and make them send their reports to the same MQTT broker, at topic `autowatcher/reporting`.
8. The service API will be available at port 8080.
9. If you need to use individual services, you can interact with InfluxDB at port 8086, with Jellyfin at port 8096, and with Mosquitto at port 1883.
10. For configuring new SLOs, create a new SLO JSON configuration and set the `SLO_FILE` environment variable of `service-api` accordingly.
11. To add new MQTT sources of information, create a new configuration for the MQTT hook, and configure a service like `qos-hook` or `nrg-hook` using this configuration (set the `CONFIG_FILE` environment variable).
